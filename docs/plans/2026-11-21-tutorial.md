# Tutorial Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Tutorial" button on the front screen that runs Professor Maple's lesson: Act 1 (a class with HUD spotlights), Act 2 (thirteen controlled lessons on hand-built boards), Act 3 (a warm-up game against Maple on Easy).

**Architecture:** The tutorial is a `Table` (the port every screen already plays through), so it runs on the real `GameScreen` with the real engine and animations. Each lesson is a hand-built `GameState` plus a list of steps (`say` / `do` / `play`). The tutorial table offers only the actions the current step expects, rigs the bag so each scripted draw comes out (`rig`), and plays Maple's scripted moves. A `Coach` overlay draws the spotlight, the ribbon, Maple and Skip on top.

**Tech Stack:** React 19, motion/react, vitest + testing-library. Engine untouched.

**Spec:** `docs/specs/2026-11-21-tutorial-design.md`

## Global Constraints

- English copy, lines as in the spec (with the review notes folded in).
- Nothing random inside the tutorial: every draw is rigged, every Maple move scripted. The warm-up game (Act 3) is a real game.
- Positions are never written: the target space glows (spotlight), for the player and for Maple.
- Skip is always visible inside the ribbon, with an inline confirm ("Leave the lesson?" Yes / Keep going); no browser dialogs.
- Holding "give up" inside the tutorial leaves the tutorial.
- The tutorial forces `cardGlow` and `bagComposition` on; `opponentThinks` off.
- Ribbon: forest green with brass border (as `.turn-banner` on your side). Overlay ≈ 85% black.
- Professor Maple art does not exist yet: placeholder is the opponent portrait. A prompt for the real art goes in `docs/plans/2026-11-10-v3-art-prompts.md`.

## Review Focus

- A `say` step must not let a tap reach the game under it (the screen shows the next step's actions as a preview). Test in Task 4 (perform rejected outside `do`) and Task 6 (full catcher in `say`).
- End turn while only "Fire up?" is open performs two actions synchronously (`skipFireUp`, `endTurn`); both must be accepted in one tick. Test in Task 4.
- Bag never empties by accident (would fire the Final turn banner): every lesson's bag has filler except 2.13. Test in Task 3 (`endTriggered` false at the end of every lesson but 2.13).
- A spotlight target that is not on screen yet (Score tab before the card rises) must not crash or leave a hole at 0,0. Test in Task 6.
- Leaving mid-lesson and starting again begins at Act 1 with a fresh board. Test in Task 7.

### Task 1: Scenario builder and bag rigging

**Files:** Create `apps/web/src/game/tutorial/scenario.ts`, test `apps/web/src/game/tutorial/scenario.test.ts`.

**Produces:**
- `type TokenSpec = DragonType | [DragonType, DragonType]`; `token(spec): Token`.
- `scenario(spec: { board?: Record<HexKey, TokenSpec[]>; held: TokenSpec; bag?: TokenSpec[]; hand?: string[]; opponentHand?: string[]; deck?: string[]; coins?: number; filler?: number }): GameState` — seat 0 to play, `phase: 'play'`, pending `[{ kind: 'place', token: held, fireUpAllowed: true }]`, log `[{ seat: 0, action: { type: 'draw', token: held } }]`, bag = `bag` + `filler` (default 12) singles cycling `DRAGON_TYPES`, extras `oneOfEach()`, cards by id from `DECK` (deck defaults to the rest of `DECK` not in either hand), rng `seedFrom('tutorial')`, 3 coins each by default.
- `rig(state: GameState, wanted: readonly Token[]): GameState` — reorders `state.bag` so the next `wanted.length` picks from `state.rng` are `wanted`, in order (pick depends only on length). Throws if a wanted token is not in the bag.

- [ ] Tests: scenario puts the board, held token and hands in place and `legalActions` offers `place` on empty spaces; `rig` then `drawMany` (via a bread fire-up) yields the wanted tokens in order; `rig` with three for a crystal gives the crystal pick those three in order; `rig` throws for a token not in the bag. FAIL → implement → PASS → commit.

### Task 2: Steps, matching, cursor

**Files:** Create `apps/web/src/game/tutorial/script.ts`, test `script.test.ts`.

**Produces:**
```ts
type UiEvent = { kind: 'openSettings' } | { kind: 'closeSettings' } | { kind: 'inspect'; hex: HexKey }
type Expect = { action: Partial<Action> } | { ui: UiEvent } | { undo: true }
type Step =
  | { kind: 'say'; text: string; spots?: string[] }
  | { kind: 'do'; text: string; spots?: string[]; expect: Expect[]; draws?: TokenSpec[] }
  | { kind: 'play'; action: Action; spots?: string[]; draws?: TokenSpec[] }
type Lesson = { id: string; act: 1 | 2; build: () => GameState; steps: Step[] }
matches(action: Action, want: Partial<Action>): boolean   // deep partial; string arrays compare as sets
offered(steps: Step[], index: number, done: number, actions: Action[]): Action[]
uiMatches(event: UiEvent, want: UiEvent): boolean
```
`offered`: a `do` step whose `expect[done]` is an action → the actions matching it; a `say` step → what the next step would offer (the preview); anything else → `[]`.

- [ ] Tests: `matches` on place/at, coinDiscard ids in either order, nested hexes; `offered` for do, say-preview, ui step, play. FAIL → implement → PASS → commit.

### Task 6: Coach overlay

**Files:** Create `apps/web/src/components/Coach.tsx`; styles in `styles.css`; test `Coach.test.tsx`.

**Produces:** `Coach({ act, step, busy, onNext, onSkip, onPlay, onMenu })`.
- Visual layer: SVG mask, holes padded 8px with 14px radius around every `spots` element found (`querySelectorAll`, re-measured every 150ms and on resize); targets not found are left out.
- Catcher: `say` → full screen, a tap calls `onNext`; `do` → `clip-path: path(evenodd …)` with the holes cut out, so only the spot answers; `play` → no ribbon, dim with holes, taps pass nowhere.
- Hidden while `busy` (fades in 200ms when idle).
- Ribbon: act 1 and 3 centred with a large portrait above; act 2 under the opponent plate. `say` shows ▸. Skip link → inline confirm.
- Act 1 → 2: the portrait flies to the plate avatar (skipped under reduced motion).
- Act 3: "You've got the knack of it. Fancy a warm-up game against me? I'll go easy on you." with "Let's play" / "Back to menu".

- [ ] Tests: say renders text + ▸ and a tap calls onNext; do has no ▸ and a tap on the catcher does not call onNext; Skip → confirm → Yes calls onSkip; act 3 buttons call onPlay/onMenu; a spot not in the DOM renders no hole. FAIL → implement → PASS → commit.
